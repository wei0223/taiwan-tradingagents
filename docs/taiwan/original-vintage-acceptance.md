# 原件數值與歷史版本驗收

本流程審查可核對的原文與數值，不改既有預測或發布時間。

## 數值審查

`original_review.audit` 驗證官方索引、公司、原件 bytes/SHA256、完整原文引句、數字字串、單位倍率與具名影響結論。
只有公司、精確公布時刻及完整主旨都唯一對應時才合併舊清單別名，保留每個原 event_id 與索引雜湊；沒有主旨者不靠時間合併。

```console
python -m tradingagents.research audit-original-values --research research.json --review-input review-input.json --transcriptions numeric-review-input.json --output-dir new-audit
```

數值核對後仍分開：已核對指定現值、未完成模型影響範圍。已發股數／授權／訂價不能證明季度加權稀釋資格；預算不當現金支出；背書保證不當借款或費用。
`upgrade` 的 extension-input 可帶 `source_numeric_reviews`，拒絕不合格抄錄後才產生報告。`valuation_latest_reported` 必須是已核對獲利季度；`valuation_eps_originals` 每季保留合併範圍與原件，不能從月營收推進獲利期間。

## 可接受的歷史證明

`vintage.knowledge` 支援兩種資格：

1. 當時已捕獲的原始版本，且公布／可用時間不晚於研究起點。
2. 後來取得的官方歷史版本證明，必須從保存的官方回應原文綁定公司、物件、精確版本及有效期間；以版本內容雜湊或官方明示不可變的版本附件綁定實際原件。

第二條不要求官方一定公布 SHA256，但不可變版本附件必須有官方版本登錄證明、精確下載 URL、相同版本識別及已核對的實際 bytes。普通可替換檔名不符合。
程式目前支援保存為 JSON 的官方版本登錄契約：`official_content_addressed_version_history` 或 `official_immutable_attachment_version_history`。這是來源介接契約，**並不表示 MOPS 已提供該契約，或七筆歷史對應已通過**。現有歷史清單未取得符合條件的證明，不能自己生成契約當官方證據。

登錄原文必須包含版本公布／替換期間及歷史覆蓋截止；晚於研究起點的原件和證明保留真實捕獲時間。已被替換的版本不能越過替換時點使用。原始數值、EPS 分母口徑與股本事件另行核對。回顧重建通過也不表示當年曾正式發布該預測。

舊上傳日期、語言順序、檔案大小、時間相近、現在顯示無更正，及人工 reviewed 布林值，皆不足以證明歷史版本。

## 持續版本保存

`refresh-sources` 追加來源快照，現在另輸出每家公司 `stock-monthly-vintages.json`：重新解析官方原件後保存月營收原文定位、原件雜湊、觀測版識別及實際捕獲時間。未證明公布時刻時保留 null，只從捕獲時刻可用，不當初次公布實績。
正規化數值列雜湊與 HTTP 原件雜湊分開，兩者不能混稱。
來源拒絕的24小時冷卻現在跨程序保留，重啟不會重試受限站台；來源恢復也不回填舊版本。
